# Chapter II — The Epistemic Verdict Engine & P(Solvency)

*Important framing before anything else: this chapter describes a heuristic self-reflection tool, not a scientific instrument. "P(Solvency)" is not a validated statistical model and it does not sit in judgment of either person or of the relationship's worth. It scores one narrow thing — whether the current household workload arrangement looks sustainable on paper — the same way a small-business cash-flow snapshot tells you about this month's operations, not about whether the business (or its owners) are good people.*

## What the Verdict Engine is for

Every long-running household eventually gets asked, in one form or another: "is this actually working?" Usually the question gets answered with whichever incident happened most recently — last night's dishes, this morning's tone. That answers the wrong scope.

The Verdict Engine asks a narrower, calmer question: **based on what's actually written in the ledger this month — hours logged in the Lemonade Stand, tasks with a named owner in the RACI table, and self-reported autonomic load — does the current workload arrangement look sustainable, or is it quietly running a deficit?**

## The inputs

P(Solvency) is a weighted read of three ledger inputs, each already covered elsewhere in this book:

| Input | Source | What it captures |
|---|---|---|
| Workload balance | Lemonade Stand (Ch. III) | How evenly visible hours are distributed |
| Ownership clarity | RACI Treaty (Workpaper 03) | How many recurring tasks have a clear, undisputed owner |
| Autonomic load | Nervous System Ladder (Ch. II sidebar) / ASI (Workpaper 02) | How much of the friction is workload versus baseline stress |

## A plain-language formula

Rather than a black-box score, treat P(Solvency) as a simple weighted read:

```
solvency_read = (workload_balance_score * 0.4)
              + (ownership_clarity_score * 0.35)
              + (1 - average_autonomic_saturation) * 0.25
```

Each component is scored 0–1 from the workpapers, not from a mood in the moment. The output is a number between 0 and 1, and it's meant to be read as a **snapshot**, not a sentence:

- **Above ~0.7:** The current arrangement is carrying its own weight. Keep the same rhythm of check-ins.
- **0.4–0.7:** Something in the three inputs is drifting — usually ownership clarity first. Revisit the RACI table before anything else.
- **Below ~0.4:** The workload as currently structured isn't sustainable. That's a statement about the *arrangement*, not about either person's love, effort, or worth — arrangements get renegotiated all the time.

## What this number is not

It is not a relationship-compatibility score. It is not a fairness verdict about who's the better partner. It does not use anyone's tone of voice, private thoughts, or communication style as an input — only the three ledger sources above, which both people fill in together. If it's ever used to end a conversation ("well, the number says...") instead of start one, it's being misused. The number's only job is to give two people a shared, low-drama starting point for the conversation Chapter V calls closing the books.
