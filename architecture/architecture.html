Architecture Review

How TOL-OS is structured and why we made these choices.

1. Why This Architecture?

TOL-OS is built on three core convictions:

  • Visibility before change. You can't fix what you can't see. This system makes invisible work visible to both people at the same time.
  • Structure over willpower. Good intentions die under stress. This framework survives stress because it's structural — a regular rhythm, clear ownership, shared metrics.
  • Nervous system first. Everything here acknowledges that you can't think clearly when you're dysregulated. The Ladder (ventral, sympathetic, dorsal) is the foundation because state-checking comes before any conversation.

2. Carrier Wave vs. Payload

In communication theory, the "carrier wave" is the structure that carries the message. The "payload" is the message itself. In TOL-OS:

  • Carrier Wave: Weekly check-in, shared document, same metrics every time
  • Payload: The actual tasks, the actual feelings, the actual workload

We spent a lot of effort on the carrier wave because the payload keeps changing. Your jobs change. Your health changes. The number of dishes changes. But if the carrier wave is solid — if both of you know when you're sitting down, what you're measuring, how you're measuring it — you can handle any payload.

3. Maintenance Margin

A bridge designed to carry 100 cars, but carrying 100 cars constantly, will fail. Every structure needs headroom. In relationships:

  • Workload should be 60-75% of capacity, not 95%
  • Check-ins should happen when things are okay, not in crisis
  • Decisions should get made when energy is available, not at 11 PM after a hard day

If your household is at 95% capacity all the time, this framework helps you see it. But naming the problem is only half the solution. You actually need to reduce the load.

4. The Dual-Dial Dashboard

One dial won't work because a household has two dimensions:

  • Dial 1: Workload Balance — Is the work divided relatively fairly? (Measured in hours and clarity)
  • Dial 2: Autonomic Resilience — Are both of you able to handle the work? (Measured by nervous system state, not willpower)

You can have perfectly balanced workload and still collapse if one person is running on fumes. You can have high resilience and still resent an unfair arrangement. This system tracks both.

5. Implementation Order (What to Do First)

Week 1: State check only. No heavy conversation. Just get comfortable naming where each of you is (ventral/sympathetic/dorsal).

Week 2-3: Do the Field Audit. List everything. Don't judge it yet. Just see it.

Week 4: First hard conversation. "Here's what I see. Here's how I feel about it. Can we fix one thing?"

Week 5+: Weekly check-in. Same day each week, same 20 minutes, same metrics. The rhythm is more important than the perfection.

6. Risks & Enhancements

Risks we know about:

  • This framework works if both people want it to work. If one person is avoiding, this just makes the avoidance more visible, which can start a fight.
  • The numbers can feel cold. Some people interpret "shared metrics" as "everything is negotiable," which is exhausting.
  • It works for any two people who share time, space, work or care. Most worksheets have two columns, so groups of three or more (a larger family or a shared house) pair up or add columns on paper for now.

What we're building next:

  • Interactive training videos so you don't have to guess whether you're doing it right
  • Email sequence that walks you through the first month step-by-step
  • Peer community so you're not just doing this in isolation
  • Expanded framework for non-romantic partnerships and family systems
